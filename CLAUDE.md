# CLAUDE.md

## О проекте

Кроссплатформенное мобильное приложение для лёгкой повседневной практики переключения внимания. Приложение помогает отвлечься от навязчивых мыслей, обратить внимание на окружающий мир и расслабиться.

Не позиционировать приложение как терапию или научно доказанный метод. Не обещать лечить тревожность или гарантированно менять мысли пользователя.

## Технический стек

- React Native с Expo managed workflow.
- TypeScript.
- Expo Router для навигации.
- npm для управления пакетами.
- При создании проекта указать поддерживаемую версию Node.js в `.nvmrc` и придерживаться её.
- Задания MVP-1 хранятся в заранее подготовленном списке внутри приложения. Сервер и API не использовать.

## Структура проекта

- `app/` — экраны и маршруты Expo Router.
- `components/` — переиспользуемые UI-компоненты.
- `content/` — список заданий и пользовательские тексты; хранить данные отдельно от компонентов.
- `lib/` — утилиты.

## Доменная модель MVP-1

В MVP-1 есть только два экрана:

1. **Главный экран** — содержит кнопку запуска практики.
2. **Экран практики** — показывает задание и позволяет принять его, пропустить или завершить практику. Экран следует реализовать так, чтобы его можно было переиспользовать в дальнейшем. Другие режимы в MVP-1 не добавлять.

Каждое задание содержит текст, тип и подтип. Текст отображается крупно и переносится на новые строки при необходимости. Тип и подтип показываются под ним меньшим и менее заметным шрифтом.

### Сценарий экрана практики

- При открытии показывается случайное задание из локального списка.
- До принятия доступны кнопки «Пропустить» и «Выполнять».
- При пропуске показывается следующее случайное задание. Пропускать задания можно сколько угодно раз.
- После принятия задания оно остаётся на том же экране; доступна только кнопка «Завершить».
- После завершения пользователь сразу возвращается на главный экран.
- Системная кнопка «Назад» возвращает на главный экран без диалога подтверждения.

В MVP-1 нет таймера, авторизации и профиля. Не добавлять функции, не перечисленные в MVP-1, даже если они кажутся полезными. Предлагать такие идеи можно, реализовывать — только по запросу пользователя.

## Контент заданий

- Тексты заданий проходят ручное ревью перед добавлением в приложение.
- Не добавлять задания, которые могут провоцировать тревогу, требуют выйти из дома или взаимодействовать с другими людьми, либо предполагают опасные действия.
- Не использовать в заданиях медицинские или психотерапевтические формулировки.

## Пользовательский текст и взаимодействие

- Весь текст, отображаемый пользователю, писать на русском языке.
- Обращаться к пользователю на «ты».
- Использовать спокойный, тёплый, уважительный и бережный тон.
- Не использовать шутки, насмешки, сленг, грубые или унижающие формулировки.
- Не перегружать основной сценарий предупреждениями и лишними сообщениями.
- Не добавлять подтверждения для пропуска задания или завершения практики.

## Тестирование

- Для unit- и компонентных тестов использовать Jest (`jest-expo`) и React Native Testing Library.
- Для E2E-тестирования пользовательских сценариев использовать Detox.
- Настройку Detox можно отложить до появления первого экрана; она не должна блокировать начало разработки.
- Detox требует нативную development build; Expo Go для E2E-тестов не использовать.
- Проверить E2E-тестами основной сценарий: запуск практики, пропуск задания, принятие задания, завершение и возврат на главный экран.

## Как Claude Code должен работать

- Перед крупными изменениями — например, добавлением экрана, теста или существенным изменением логики — сначала объяснить на русском языке, что планируется сделать и зачем.
- Объяснять план достаточно подробно и простым языком для новичка; пояснять новые термины и связь изменений с проектом.
- Не создавать коммиты, если пользователь прямо этого не запросил. Если коммиты запрошены — делать их небольшими и осмысленными.
- Если требования или логика неясны, задать уточняющие вопросы, а не додумывать самостоятельно.
- Если пользователь задаёт вопрос во время работы, остановиться и ответить. Не возобновлять работу над задачей, пока пользователь не ответит.
- Не добавлять зависимости без обоснования.
- Не менять этот файл без явного запроса.
- После создания проекта добавить фактические команды запуска, проверки и тестирования.
